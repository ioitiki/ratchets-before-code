## Operator decision needed: `BUDGET`

- **Measured:** the core is **201** implementation lines against a `BUDGET` of **800**. Those 201 lines implement all of spec §4.1.
- **800 does not bind.** The spec chose 800 as a real constraint above an expected 400–600. The measured core is a quarter of 800, so the ratchet would fire only after the core roughly quadrupled.
- **Recommendation: 250.** That is 24% above today. It leaves room for the one core rule the spec still names: on restart, an intent with no outcome is re-driven if `Idempotent` and killed if `NotIdempotent` (§4.2), if plan 03 or 04 puts that rule in `ledger-core`. Anything beyond that would trip the ratchet, which is the point: per the script's own header, the budget must sit below the size the code would drift to on its own.
- **The count depends on formatting.** The same code measures 148 lines under `use_small_heuristics = "Max"` and 201 under rustfmt's defaults, which `cargo fmt` uses here because the repository has no `rustfmt.toml`. Adding one with `Max` would loosen the budget by about a quarter with no code change. If a rustfmt config is ever adopted, recount and set `BUDGET` in the same diff.
- **Not changed here.** Loosening or tightening a ratchet is the operator's call (ADR 0001).

## Deviations from the plan

1. **The plan's property tests failed the clippy gate.** `Run::step` returns `(Command, Result<Vec<Event>, Refusal>)`, and four properties call it as a statement. rustc reports a `Result` inside a discarded tuple as `unused_must_use`, which gave 5 warnings under `cargo test` and 5 errors under `clippy -D warnings` (both shown above). The fix discards the outcome explicitly with `let _ =` at those five call sites. Random sequences are meant to produce refusals, and those four properties check only events and state, so no property changed. The stale-lease property already used the outcome. The Task 4 commit keeps the plan's subject line and adds a body explaining the fix.
2. **The gate capture is inside the worktree.** The plan writes `/tmp/plan02-gates.txt`, which is outside the worktree and so forbidden by the clean-room rule. The capture went to `target/plan02-gates.txt`, which is gitignored.
3. **The gate script ran under `bash -o pipefail`, not `sh -c`.** Without pipefail, `cargo clippy … | tail -3; echo "exit $?"` prints `tail`'s status and `cargo test … | grep …; echo "exit $?"` prints `grep`'s. A failing clippy or test run would still have printed `exit 0`. The script is otherwise unchanged.
4. **Expected output that differed but needed no change:**
   - Task 1's red step failed on `unresolved import ledger_api`, not on a missing library target: the test target compiled, and there was no library for it to import.
   - In Task 2 Step 4, only `core-line-budget` reports a count (`8 of 800`). `core-purity` prints a bare `ok`, which is how that script already behaves.
   - Task 2's red run also warned that `BASE_MS` and `CAP_MS` were unused, because the `todo!` stub does not use them.
   - `cargo fmt` expanded the plan's compact code to rustfmt's defaults; `ledger-api/src/lib.rs`, for example, is 155 lines on disk. The plan runs `cargo fmt` before every commit, so this is by design. Its effect on the line count is covered in the `BUDGET` section.
